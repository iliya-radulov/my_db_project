## 0c. GitHub MCE database (roadmap priority 3) — first examination

Source: github.com/RunqingYang1996/MCEdatabase, commit 21ec937 (10 Jul
2024); paper Yuan, Yang, Patra, Liao, AIP Advances 14, 085125 (2024),
arXiv:2403.02553.

- **No licence file** in the repository (README only). Legally that means
  all rights reserved, unlike NIMS (CC BY 4.0). Decision needed before the
  data are used in a publication; not to be committed.
- Files: `modified6125.csv` (6,614 rows, raw GPT-3.5 extraction, all
  materials incl. organic), `modified1426.csv` (1,425 rows, inorganic
  only), `725.csv` / `html/725_updated.csv` (714 rows, the latter
  human-corrected, with title, DOI and Materials Project ID). Only the 714
  rows carry a DOI.
- Provenance can be recovered for the raw rows: the `source` index is the
  0-based position of the paper in the concatenated Web of Science export
  in `source/` (`savedrecs.xls`, then `(1)` … `(8)`, 8,772 records).
  Checked: for all 714 corrected rows the index matches the title's
  position; DOIs recovered for 97 % of the 6,614 raw rows; where a paper
  is in both files (539 papers) the DOI agrees in 98 %. Fourteen rows have
  sources like `948(1)` and are flagged, not guessed.
- La(Fe,Si/Al)₁₃-like rows in the raw file: 469 from 233 papers; 200 rows
  (43 %) from papers also in NIMS, 124 papers not in NIMS. Plain numeric
  values: 369 |ΔS|, 205 T_c. Fields are free text (`'5 T'`, `'0-5 T'`,
  `'nan T'`, `'10 kOe'`); values too (`'10.07 to 4.47'`,
  `'0.65(J/mol K)'`, `'Below 360'`); formulas with variables
  (`Er2-xPrxFe17`), brackets and words (`Nanocrystalline Gd`).
- Only 142 of the 469 formulas pass the lab calculator's strict parser.
  Published formulas are therefore read by a separate parser
  (`mcedb_dataset.parse_formula`): case-sensitive, so an element without
  a number means 1 (`LaFe11.6Si1.4`), brackets with multipliers expanded
  (`La(Fe0.92Co0.08)11.9Si1.1`), and anything else — variables, words,
  ranges — rejected. The lab calculator stays strict.

**Import (`import_mcedb.py`, decision 2 Nov: option (a), internal use only,
authors to be asked):**

- Corrected rows (`725_updated.csv`) → `quality_flag = 'literature_mined'`;
  raw rows → `'unverified'`; raw rows of papers in the corrected file
  (935) dropped in favour of the corrected rows.
- Values kept only when unambiguous: field `'2 T'`, `'10 kOe'`, `'0-5 T'`
  (change from 0); |ΔS| a plain number (sign dropped) in J/kg K; T_c a
  plain number. Ranges, bounds, other units, text → empty, counted. The
  extracted strings are kept in `comments` for audit.
- Filter: La(Fe,Si/Al)₁₃ family (La present, rare earths 5–9.5 at.% of
  the metal sites, Fe ≥ 55 at.%, Si or Al present).

Row accounting (7,328 rows: 714 corrected, 6,614 raw):

| Rows | Outcome |
|---|---|
| 3,734 | not La(Fe,Si/Al)₁₃ family |
| 2,364 | formula rejected (not an element: variables, words, …) |
| 935 | raw row of a paper in the corrected file |
| 52 | no usable value |
| 17 | formula rejected (unbalanced bracket) |
| 14 | source index unreadable (`948(1)`) |
| 3 | formula empty |
| **209** | **accepted**, from 106 papers, all `unverified` (the corrected file has no La(Fe,Si)₁₃ rows); T_c 125, |ΔS| with field 156; 157 composition keys |

Against NIMS: 95 of the 209 rows come from 53 papers NIMS also has; **53
papers are only in this source**. For 81 rows the paper and composition
key match a NIMS record. Extraction accuracy on those (each LLM value
compared with the nearest NIMS value for that paper and composition, so
optimistic): T_c within 2 K of NIMS for 81 % of 47 pairs (median
difference 0, worst 313 K); |ΔS| within 0.5 J/kg K for 90 % of 59 pairs
(median 0, worst 11.4 J/kg K). Worst cases: LaFe₁₁.₆Si₁.₄C₀.₂ and C₀.₁
with T_c 540 / 500 K where NIMS (and the paper) give 227 / 214 K —
another temperature picked from the text; La₀.₈Ce₀.₂Fe₁₁Co₀.₄Si₁.₆
294 vs 224 K.

## 1. Context

The series: Stage 1 captures and screens compositions, Stage 2 makes
measurements trustworthy, Stage 3 advises before synthesis, Stage 4 closes
the loop. Two Stage 4 workflows run in parallel and share only the
database:

- **Nd–Fe–B / CALPHAD** (plans A–D, ensemble of 84 binary-assessment
  combinations, discussion with H. Zhang) — handled in a separate chat,
  not part of this log.
- **Magnetocaloric literature (this log)** — idea from former colleagues:
  train a property model on a large, heterogeneous literature dataset
  (NIMS, 1,113 samples from ~220 papers and many labs) and use small,
  consistently measured series only for testing and correction, never for
  training.

Why: the hand-extracted literature set (34 records, 24 with usable |ΔS|)
was too small for a model; only one family met the gate of ~20 clean
points for leave-one-family-out evaluation.

## 5. Review of the NIMS example scripts

Not used; `evaluate.py` is a fresh implementation. Findings:

- Fail on current libraries: `mean_squared_error(squared=False)` (removed
  from scikit-learn; 1.9 installed) and `plt.cm.get_cmap` (removed from
  matplotlib; 3.11 installed).
- `process_duplicates` stores IDs such as `"132_4.0"` (sample 132 at 4 T)
  in a float array; `float('132_4.0')` reads the underscore as a digit
  separator, so the ID silently becomes 1324. IDs only, not values.
- `if Xy_names[i] != 'a@PM' or Xy_names[i] != 'c@PM'` is always true, so
  lattice constants are rounded to 0.01 Å despite the intent.
- `samples_to_delete += samples_to_delete + [...]` doubles the list each
  time (harmless).
- Evaluation is random 80/20 ShuffleSplit only. Measured effect (NIMS
  loader and model, preliminary run):

| Target | random split | whole papers held out | predict-the-mean |
|---|---|---|---|
| T_tr (n = 552, 148 papers) | MAE 6.77 K, R² 0.96 | MAE 10.27 K, R² 0.91 | 42.60 K |
| \|ΔS_M\|max (n = 870, 170 groups) | MAE 1.63, R² 0.90 | MAE 3.50, R² 0.54 | 6.02 J/kg K |

## 7. Test-set design (decided 2 November)

- **Test set = Moreno-Ramírez 2018 (Ni, doi:10.1016/j.actamat.2018.08.054)
  and 2019 (Cr, doi:10.1016/j.actamat.2019.06.022)**: co-authored by
  I. Radulov, one lab, one protocol, original data available. Both papers
  are removed from all training and cross-validation.
- Krautz 2014 (not co-authored), Thiem (published differently) and
  Gottschall 2019 (not in NIMS) are **not** excluded.
- Co-authorship alone is not leakage. `works.bib` was checked: none of its
  32 DOIs is in NIMS (the Ni and Cr entries have no DOI field there). Two
  NIMS papers likely co-authored — doi:10.1016/j.actamat.2017.01.054
  (2 rows, `LaFe11.38Mn0.32Si1.30Hx`) and doi:10.1088/1361-6463/aa893e
  (1 row) — contain none of the test samples and stay in training.
- The parent alloy LaFe₁₁.₆Si₁.₄ appears 51 times from 37 papers in NIMS,
  so x = 0 test points are easy; results are reported separately for
  x = 0 and x > 0.
- The HZDR materials library (Gottschall 2019) is consistent but covers
  14 material families with only ~2 La(Fe,Si)₁₃ rows: it cannot serve as
  the test set for a La(Fe,Si)₁₃ model.
- High-Mn series (stay 1: nominal x = 0.8–2.5, EDX 0.65–1.87; positive ΔS,
  displaced loops — antiferromagnetic / spin-glass behaviour): NIMS has one
  unhydrided row above x ≈ 0.5. Use as an out-of-range test, expected to
  fail; not for correction.

Compositions from the stay reports (EDX of the 1:13 phase):
- Ni: La1.00Fe11.2Si1.45; La1.00Fe11.2Ni0.10Si1.42; La1.00Fe11.1Ni0.18Si1.44;
  La1.00Fe10.9Ni0.26Si1.50; La1.00Fe10.9Ni0.33Si1.54.
- Cr: La1.00Fe11.5Si1.40; …Cr0.12Si1.42; …Cr0.21Si1.42; …Cr0.35Si1.42;
  …Cr0.42Si1.53; …Cr0.47Si1.59; …Cr0.56Si1.59. NIMS uses the measured

## 9. Reading Origin data without Origin

Problem: the original measurements are in Origin files, and there is no
Windows computer or Origin licence available.

Finding: an Origin graph pasted into PowerPoint is an OLE object
(`ppt/embeddings/oleObjectN.bin`, ProgID `Origin50.Graph`) whose
`Contents` stream is a complete Origin project (`CPYA 4.3024 45 W64`),
with all plotted datasets. Block structure: `[int32 size]['\n'][payload]['\n']`;
a dataset is a 146-byte header with its short name at offset 88,
followed by a value block; values are float64 stored either as 8 bytes or
as a 2-byte flag + 8 bytes (detected per column).

Attempt to build the open-source liborigin from GitHub was blocked by the
sandbox (outside code); `origin_from_pptx.py` is a from-scratch reader
(Python + olefile).

Validation: the extracted Ni table matches NIMS (section 6); the peaks of
the seven Cr ΔS(T) curves (stay 2, slide 21) are 22.43, 21.52, 21.18,
17.32, 14.97, 11.53, 6.65 J/kg K against NIMS 22.4, 21.4, 21.1, 17.0,
14.9, 11.5, 6.7.

Limitations: numeric columns only; short names (`Book1_A`, `Ni01_C190`),
no long names or units — map columns to samples via the slide legend;
standalone `.opj`/`.opju` files not handled yet.

What the slides contain (stay 1: 19 graphs with data; stay 2: 18): XRD
patterns, M(T), ΔS(T) at 1.9 T per sample, ΔT_ad(T), summary tables
(T_tr, |ΔS|, ΔT_ad vs x), lattice parameter vs x, high-Mn M(T) and ΔS;
for Cr also measured x with EDX errors, annealing temperature per x
(1100, 1106, 1113, 1125, 1150, 1150, 1150 °C — supplies the missing NIMS
value for x = 0), hysteresis (1.8, 2.3, 4.3, 2.8, 0.5, 0.5, 0 K), a
second-phase fraction rising to 24.5 % at x = 0.56 (column unlabelled;
check), the field-dependence exponent n(T) (slide 22) and direct ΔT_ad
curves (slide 25). Ni: Rietveld α-Fe 0.2 → 21.3 wt % with Ni (so |ΔS|
per kg is diluted at high Ni).

Exports: one CSV per graph, `python origin_from_pptx.py <pptx> <out_dir>`.

### Reading

- Random splits flatter: ΔS 1.7 vs 3.3 J/kg K on unseen papers. Only
  grouped evaluations are reported as results.
- Keeping rows with missing annealing data improves the paper-level ΔS
  error (3.73 → 3.32); test-set differences of ~0.3 on 11–12 points are
  noise.
- Cr series: the tree model, with ~5 other Cr rows in training, predicts
  a nearly flat T_tr (~188 K) and ΔS (~15–16 J/kg K) for x ≥ 0.35 while
  the measured values fall to 170 K and 6.7 J/kg K. Trees do not
  extrapolate; ridge (linear in Cr content) follows the T_tr trend
  better (6.9 vs 10.3 K on substituted test samples). Motivates the
  correction step and, possibly, a linear or physics-informed component.
- The Ni series is predicted well (LOFO T_tr ≈ 3–4 K).

### 10b. Step 5 — correction on the consistent series

Command: `python correct.py --target {T_tr --restore-T-tr | dS} --base {gbr | ridge} [--curve]`.
Base model trained on NIMS without the two test papers. Corrections
(fitted on consistent points only): `offset` (mean residual of the other
consistent points), `series_offset` (same series only), `gp` (Gaussian
process on residuals; inputs substituent at.%, Si at.%, field). References
without NIMS: `series_mean`, `series_linear` (straight line in
substituent content through the other points of the series).

**Success criterion, fixed before the first run:** a correction is useful
if its leave-one-out MAE is at least 20 % below the base model's for both
T_tr and |ΔS|, and below `series_mean`.

Leave-one-out MAE on the 12 consistent points (5 Ni, 7 Cr):

| Correction | T_tr, GB base | T_tr, ridge base | \|ΔS\|, GB base | \|ΔS\|, ridge base |
|---|---|---|---|---|
| none | 9.34 K | 7.47 K | 3.16 | 4.83 J/kg K |
| offset | 8.42 | 4.29 | 2.88 | 2.15 |
| series_offset | 7.16 | 2.97 | 3.16 | 2.44 |
| gp | 8.15 | 4.84 | 2.08 | 2.17 |
| series_mean (no NIMS) | 7.85 | 7.85 | 5.85 | 5.85 |
| series_linear (no NIMS) | 3.01 | 3.01 | 2.13 | 2.13 |

Against the criterion: with the GB base no correction meets it for both
targets (series_offset −23 % for T_tr only, gp −34 % for |ΔS| only); with
the ridge base all three meet it (offset −43 % / −56 %, series_offset
−60 % / −49 %, gp −35 % / −55 %).

But a straight line through the other points of the same series, with no
NIMS at all, is as good as the best corrected model (3.01 K, 2.13 J/kg K).
With most of a series known, NIMS adds nothing. The realistic question is
the start of a new series, hence the **new-series curve** (`--curve`):
MAE on the remaining samples of one series from k known samples of that
series (all choices of k, averaged; the other series not used).

Reading:
- The NIMS prior pays off for the first one to three samples of a new
  series — exactly when the next sample is being chosen. Ridge + offset is
  the most robust choice there (Ni T_tr 3.7 K vs 10.4 K for the series
  mean at k = 1; Ni |ΔS| 1.6 vs 8.0).
- From k ≈ 3 on Cr, a straight line through one's own data overtakes;
  for Ni, whose T_tr is not linear in x, ridge + offset stays ahead.
- Only two series (5 and 7 points): indicative, not proof. The natural
  extension is more consistent series (high-Mn, Thiem T_c, others).

## 14. Lessons so far (for the paper)

| Defect | How found | Fix | Lesson |
|---|---|---|---|
| Header with a trailing space (`'|ΔSM|max (J/kg K) '`); a lookup by the obvious name silently returns an empty column | opening the real file | exact-header check, fail loudly | never trust a column name from a description |
| Composition strings unusable for most rows | counting non-empty, parseable strings | element columns | check coverage before choosing a field |
| Random split doubles the apparent ΔS accuracy | re-running the NIMS model with papers held out | grouped evaluation only | evaluation design matters more than the model |
| 22 of 34 "test" records already in the training pool | DOI overlap check | test papers removed from training | check provenance before calling data independent |
| Hand-made power-law estimates off by up to 37 K | comparison with NIMS and original data | use reported values | estimates are not data |
| IDs mangled by `float('132_4.0')` in third-party code | tracing a KeyError | own implementation | underscores are digit separators in Python numbers |
| Float ID from `iterrows()` broke the import | throwaway-database test | `int()`; single transaction rolled back cleanly | test imports on a disposable database |
| "Unreadable" Origin data was inside the PowerPoint files | inspecting the embedded OLE objects | `origin_from_pptx.py` | look inside the container before digitising |
| The GUI's file import writes samples with composition `{'placeholder': 1.0}`, which a key function would have accepted as an element | reading the GUI code while designing the key | element-symbol check | validate keys against the domain (real element symbols), not just the type |
| Composition keys computed after rounding to 4 decimals differed from keys of the unrounded values (660 vs 659 distinct) | dry-run count vs database count | one code path, key from unrounded values | never round twice; report from the same code that writes |
| Composition parser skipped brackets: `La(Fe0.92Co0.08)11.9Si1.1` became La 0.92, Fe 0.08, Co 11.9, Si 1.1, and the element/number count check still passed | a literature formula that the "strict" parser should have rejected was accepted | reject every character except letters, digits, `.`, spaces (stage one and two parsers); query in `SERVER_SETUP.md` §4b to find affected samples | a count check is not a structure check; test parsers with the real input they will meet |
| `pd.NA` (pandas' missing value in text columns) cannot be stored by psycopg2; the first GitHub import failed | throwaway-database test; the transaction rolled back, nothing written | `clean()` handles `pd.NA` / `pd.NaT` | every missing-value type of the libraries in use must be mapped to NULL |
| The pre-registered criterion passed (ridge base), yet a straight line through one's own series did as well | adding a no-NIMS reference | new-series curve | a success criterion must include the simplest competitor |
